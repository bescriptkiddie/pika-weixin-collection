人机共创内容生成闭环

Open Design Draft · 人定方向，AI 扩大生产力，人机一起调优

North Star

从“抓文章”升级为人机共创的内容生成器。

人决定信息源、话题、受众和发布边界；AI 负责采集、整理、聚合和草稿生成；人和 AI 再一起复盘调优。

闭环阶段

把线性的爬虫，改造成由人控制方向的内容生成循环。

人给方向和判断，AI 给候选和草稿；每一步都产出可检查文件，不依赖某个单一平台。

人审分发

人改写、确认风险和语气后，再接外部渠道。

共调反馈

采纳、删除、改写理由、发布效果一起回流。

关键缺口跨来源内容池、人工决策记录、生成与分发反馈。

当前选中阶段

人定信息源

人决定哪些来源值得进入系统，AI 不自动扩张信息边界。

微信公众号已经可抓取，并能导出 Markdown 和 llm_wiki raw sources。
增加 GitHub、RSS、手动收藏等外部源配置，并记录是谁、为什么加入。
`external_sources.json`、source adapter、raw source files、human_reason。
设计判断

Horizon 应该由人确认接入理由后，作为 `github_repo` 信息源进入系统，而不是写入 `name2fakeid.json`。

保留

公众号主链路保持稳定

`name2fakeid.json`、微信凭证、正文缓存和现有前端阅读体验继续保留，不为外部源重构爬虫主逻辑。

新增

外部源走独立适配器

`Horizon`、RSS、手动链接进入 `external_sources.json`，由人确认来源价值，再由 adapter 输出统一 RawItem。

避免

不要把所有东西塞进公众号

用伪 fakeid 会让后续去重、评分、生成、分发都变得混乱。兼容展示可以有，但底层模型要分清。

Human In The Loop

人不是最后的审核人，而是整个系统的控制面。

这个产品更像“内容驾驶舱”：人给方向、边界和判断，AI 给候选、聚合、草稿和复盘建议。

人决定

信息源和话题

哪些公众号、仓库、RSS 和手动收藏进入系统，今天要围绕什么问题写，都由人确定。AI 可以建议，但不能自己扩张边界。

AI 执行

整理和成稿

AI 负责抓取、清洗、去重、摘要、聚类、评分，并按人的话题生成多个版本草稿，而不是替人决定要写什么。

人机共调

反馈变成下一轮策略

采纳、删除、改写、继续深挖、不感兴趣和人工备注必须写回后端，影响下一轮排序、选题和模板。

闭环判定

只要人的反馈能改变下一轮来源权重、素材排序、选题建议或生成模板，它就是闭环；如果只是记录在前端，它仍然是流水线。

Source Strategy

来源多样化，采集协议分离，输出格式统一。

这层的目标是把“能抓什么”从“怎么生成内容”里拆出来。

Horizon 接入

`github_repo` 适配器

抓 README、docs、releases 或 repo activity，生成 `raw/sources/github/horizon/*.md`。

前端兼容

可展示为 GitHub / Horizon

如果需要出现在现有信息流，做一层展示兼容；但底层不要写进 `name2fakeid.json`。

边界

外部源不触碰微信凭证

微信 token/cookie 只服务公众号抓取，外部源适配器不依赖它，避免权限和失败状态互相污染。

Data Contracts

后面能不能人机共调，取决于有没有记录人的判断。

先用 JSON/JSONL 文件落地，之后再迁移数据库也不改变上层生成逻辑。关键是保留 human intent、decision 和 feedback note。

SourceConfig

{ "id": "horizon", "type": "github_repo", "name": "Horizon", "url": "https://github.com/Thysrael/Horizon", "enabled": true, "options": { "include": ["README", "docs", "releases"] } }

RawItem

{ "id": "github:horizon:readme", "source_id": "horizon", "source_type": "github_repo", "title": "Horizon README", "url": "...", "content_markdown": "...", "fetched_at": "..." }

ContentItem

{ "id": "...", "source_name": "GitHub / Horizon", "published_at": "...", "summary": "...", "tags": ["信息源", "AI"], "score": 0.82, "dedupe_key": "...", "human_decision": "candidate" }

FeedbackSignal

{ "item_id": "...", "event": "draft_reviewed", "human_decision": "rewrite", "feedback_note": "观点不够强", "channel": "local_web", "created_at": "...", "weight": 1.0 }
数据迁移判断

短期可以兼容 `message_info.json`，但中期应该新增 `content_items.jsonl` 和 `feedback_events.jsonl`。否则来源一多、反馈一多，公众号字段会承载太多非公众号语义。

Implementation Roadmap

先把人的控制点落下来，再让 AI 扩展采集和生成。

这个顺序能保持现有项目可用，同时让架构逐步从“公众号应用”升级为“人机共创内容生成器”。

1

外部源配置

  • 新增 `external_sources.example.json`
  • 配置 `github_repo:horizon`
  • 记录人为什么添加这个来源
2

GitHub 导入脚本

  • 新增 `scripts/import_external_sources.py`
  • 抓 README、docs、releases
  • 输出 `raw/sources/github/horizon/*.md`
3

统一内容池 + 反馈

  • 新增 `content_items.jsonl`
  • 新增 `feedback_events.jsonl`
  • 记录采纳、改写、删除和人工备注
4

草稿工作台

  • 人输入话题和受众
  • AI 生成多版本草稿
  • 人改写确认后再分发
